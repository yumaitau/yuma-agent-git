# Residency matrix (DRAFT)

> DRAFT, not approved. Issue #68, decision record
> [ADR 0005](adr/0005-residency.md) (Proposed). This page describes where data
> lives **today** and how, if at all, that is enforced. It is not a statement
> that any data stays in Australia, and nothing in it may be quoted as one.

Checked against `worker/wrangler.jsonc`, `worker/src/env.ts` and `worker/src`
on local `main` on 17 October 2026. Cloudflare behaviour is from its public
docs on the same date (links in ADR 0005).

How to read the columns:

- **Holds**: the customer data that ends up there.
- **Location today**: what we know. "Not recorded" means the resource exists
  but this repo does not say where Cloudflare placed it; read it from the
  Cloudflare dashboard before relying on it.
- **Enforcement today**: what the code or config does to control location.
  "None" is the honest answer for most rows.
- **Option 1 control**: what ADR 0005 option 1 would add, and whether that is
  a guarantee or a hint.

## Bindings in `worker/wrangler.jsonc`

The base config is what local development and tests use. `env.prod` is the
Yuma production deployment. Wrangler does not inherit bindings into an
environment, so `env.prod` repeats them; `assets`, `observability`, `triggers`
and the Durable Object `migrations` are declared once at the top level.

## Gaps before any residency claim

- No resource has a location hint or jurisdiction.
- No per-org residency setting, so nothing can return `residency_restricted`.
- R2 blobs are plaintext.
- Each shard database (ADR 0006) would need its own location hint, and the
  SSH gateway (ADR 0007) its own host in Australia; neither exists yet.
- Queues, Workers Logs, Workers AI, Containers, Cache API and account metadata
  have no documented location control on Cloudflare.
- No production backups exist yet.
- The forge serves from `workers.dev`, where Regional Services cannot apply.
